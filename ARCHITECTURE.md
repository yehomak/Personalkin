## Components

### Personalkin MCP server
- **Type:** FastMCP, stdio transport
- **Entry point:** `server.py`
- **Tools:** 17 registered functions across spending, calendar, and health
- **Access:** read-only to all data sources

### SpendWisely (DuckDB)
- **Location:** `~/Projects/SpendWisely/db/spendwisely.duckdb`
- **Populated by:** SpendWisely Docker backend, which imports bank CSV exports and runs AI categorization
- **Schema:** `transactions` table with booking date, counterparty, amount, currency, category, direction (`expense`/`income`/`internal`)
- **Note:** requires SpendWisely Docker to run at least once to flush WAL

### MyCalendar (MongoDB Atlas)
- **Location:** cloud, always available
- **Collections:** `events`, `categories`
- **Times:** stored as ISO UTC strings

### Garmin (DuckDB)
- **Location:** `~/Projects/garmin-sync/garmin.duckdb`
- **Populated by:** `garmin-sync/sync.py` (separate repo, own venv), run daily via cron
- **Schema:** `health_days` (daily metrics: sleep, HRV, HR, body battery, stress, readiness) + `health_activities` (per-session: type, duration, HR zones, training effect, training load)

### Gmail MCP
- **Type:** claude.ai built-in integration, not part of this server
- **Auth:** session-based via `/mcp` in Claude Code
- **Use:** cross-referencing receipts, booking confirmations, invoices with transaction data

### scripts/ — automation pipeline
Cron-driven pipeline that syncs data, generates report files, and sends macOS notifications:

| Script | Schedule | Actions |
|---|---|---|
| `run_daily.py` | Tue–Sun 10am | garmin sync → activities → notify (sleep/HRV/readiness) |
| `run_weekly.py` | Mon 10am | garmin sync → activities → weekly report → notify (tap-to-open) |
| `run_monthly.py` | 1st 10am | monthly report (prev month) → notify (tap-to-open) |

Generator scripts (called by runners, also usable standalone):
- `generate_activities.py` — one `.md` per activity session
- `generate_report.py` — weekly narrative report with sparkline trends
- `generate_monthly_report.py` — monthly summary with fitness trajectory
- `generate_profile.py` — comprehensive health reference document

### context/ files
Markdown files read manually at session start for personal background. Organized into:
- `me/` — identity, goals, direction, current state, work context, travel log
- `health/` — `profile.md` + `reports/` (weekly/monthly) + `activities/` (per-session)
- `work/` — daily updates summary, developer notes

Health files are auto-generated by scripts; `me/` and `work/` files are maintained manually.

## Data flow

**Spending query:**
```
User asks → Claude calls MCP tool → Personalkin queries DuckDB → returns JSON → Claude formats answer
```

**Calendar query:**
```
User asks → Claude calls MCP tool → Personalkin queries MongoDB → returns JSON → Claude formats answer
```

**Health live query:**
```
User asks → Claude calls MCP tool (e.g. get_health_snapshot) → Personalkin queries Garmin DuckDB → returns JSON
```

**Health report query:**
```
User asks → Claude calls get_latest_health_report → Personalkin reads context/health/reports/YYYY-WXX.md → returns full text
```

**Cross-reference (spending + email):**
```
User asks about a charge → Claude queries DuckDB for transaction → Claude searches Gmail for matching receipt → Claude correlates and answers
```

**Context-aware session:**
```
Session starts → Claude reads context/me/now.md + context/me/core.md → User asks question → Claude uses MCP tools with awareness of personal context → answer is grounded in both data and life context
```

## Extension points

**New data source:** add a new `tools/*.py` file, register in `server.py`, add env var for credentials.

**New tool on existing source:** add function to `tools/spending.py`, `tools/calendar.py`, or `tools/garmin.py`, register in `server.py`.

**New scheduled report:** add a generator script in `scripts/`, call it from the appropriate runner.

**Potential additions:**
- `get_past_events(days)` — look back at what happened
- `get_net_worth_snapshot()` — if a savings/investment source is added
- `search_transactions(query)` — full-text search on counterparty/title
- `get_category_trend(category, months)` — track a category over time
